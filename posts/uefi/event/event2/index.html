    事件类型

    SignalEvent#

    触发 EVT_NOTIFY_SIGNAL 类型事件

    • CoreReleaseEventLock -> CoreRestoreTpl -> CoreDispatchEventNotifies -> Event->NotifyFunction (Event, Event->NotifyContext);
    • SignalEvent中会对 Event->SignalCount 置位
      • 对于 EVT_NOTIFY_SIGNAL 类型的事件 会清除 Event->SignalCount
      • 对于其他类型事件 有其他类似事件触发函数进行清除
    • 加锁过程
      • 会将 gEfiCurrentTpl 升级为锁自身的tpl。而锁自身的TPL是TPL_HIGH_LEVEL。因此加锁时gEfiCurrentTpl升级为最高
      • 会将 原本Tpl 存储在 Lock->OwnerTpl
    • 解锁过程
      • 将 gEfiCurrentTpl 恢复为原本的Tpl,也就是恢复为Lock->OwnerTpl
    • 将目标事件加入对应优先级的事件队列 gEventQueue 中等待触发
    • 在CoreRestoreTpl过程中，找出优先级队列中高于恢复后Tpl的最高优先级事件进行触发。

    普通事件#

    • 加锁 CoreAcquireLock

      • 升级当前任务优先级 gEfiCurrentTpl 为锁的优先级 Lock->Tpl - TPL_HIGH_LEVEL
      • 原任务优先级 gEfiCurrentTpl (TPL_APPLICATION) 存储在 Lock->OwnerTpl
      • 锁的状态改为 EfiLockAcquired
      • 关闭 中断

    • Event->SignalCount++

    • 对于 EVT_NOTIFY_SIGNAL 类型事件 调用 CoreNotifyEvent

      • 如果已经存在队列中，则移除排队队列 Event->NotifyLink
      • 加入待通知队列 gEventQueue ，通过 SignalLink 节点
      • 置为对应的优先级掩码 gEventPending

    • 释放锁 CoreReleaseEventLock

      • 恢复 Tpl 值为加锁前的tpl // gEfiCurrentTpl: TPL_HIGH_LEVEL Lock->OwnerTpl : TPL_APPLICATION
      • 释放锁Lock->Lock = EfiLockReleased;
      • 恢复任务优先级 值为加锁前的TPL// CoreRestoreTpl(Tpl)
        • 在 各个优先级事件掩码 gEventPending 中找到高于Tpl的事件优先级掩码(掩码从高往低取)
          • 将此掩码值赋值给 gEfiCurrentTpl
          • 如果掩码值 小于 最高优先级 TPL_HIGH_LEVEL 则开 中断
          • 执行内核事件派遣通知函数 CoreDispatchEventNotifies
            • 加锁 CoreAcquireLock //gEfiCurrentTpl: TPL_HIGH_LEVEL Lock->OwnerTpl : TPL_HIGH_LEVEL
            • 找到当前事件优先级队列//Head = &gEventQueue[Priority]; //循环，对于普通事件只有一次
            • 移除排队队列 Event->NotifyLink
            • 对于 EVT_NOTIFY_SIGNAL 类型事件
              • Event->SignalCount = 0;
            • 释放锁 CoreReleaseEventLock //gEfiCurrentTpl: TPL_HIGH_LEVEL Lock->OwnerTpl : TPL_HIGH_LEVEL
            • 通知注册在事件中的回调 Event->NotifyFunction (Event, Event->NotifyContext);
            • 加锁 //继续循环 //gEfiCurrentTpl: TPL_HIGH_LEVEL Lock->OwnerTpl : TPL_HIGH_LEVEL
          • 取消掩码位
          • 释放锁 CoreReleaseEventLock
      • 恢复任务优先级 gEfiCurrentTpl = NewTpl; // gEfiCurrentTpl: TPL_APPLICATION Lock->OwnerTpl : TPL_APPLICATION
      • end

    事件组事件#

    • 加锁 CoreAcquireLock

      • 升级当前任务优先级 gEfiCurrentTpl 为锁的优先级 Lock->Tpl - TPL_HIGH_LEVEL
      • 原任务优先级 gEfiCurrentTpl (TPL_APPLICATION) 存储在 Lock->OwnerTpl
      • 锁的状态改为 EfiLockAcquired

    • Event->SignalCount++;

    • 对于 EVT_NOTIFY_SIGNAL 且是事件组类型事件

      • 遍历 gEventSignalQueue 中所有事件取出目标GUID一致的事件组 调用 CoreNotifyEvent
        • 移除排队队列 Event->NotifyLink
        • 加入待通知队列 gEventQueue ,通过 SignalLink 节点
        • 置为对应的优先级掩码 gEventPending

    • 释放锁 CoreReleaseEventLock

      • 恢复 Tpl 值为加锁前的tpl // gEfiCurrentTpl: TPL_HIGH_LEVEL Lock->OwnerTpl : TPL_APPLICATION
      • 释放锁Lock->Lock = EfiLockReleased;
      • 恢复任务优先级 值为加锁前的TPL// CoreRestoreTpl(Tpl)
        • 在 各个优先级事件掩码 gEventPending 中找到高于Tpl的事件优先级掩码(掩码从高往低取)
          • 将此掩码值赋值给 gEfiCurrentTpl
          • 如果掩码值 小于 最高优先级 TPL_HIGH_LEVEL 则开 中断
          • 执行内核事件派遣通知函数 CoreDispatchEventNotifies
            • 加锁 CoreAcquireLock //gEfiCurrentTpl: TPL_HIGH_LEVEL Lock->OwnerTpl : TPL_HIGH_LEVEL
            • 找到当前事件优先级队列//Head = &gEventQueue[Priority]; //循环，
            • 移除排队队列 Event->NotifyLink
            • 对于 EVT_NOTIFY_SIGNAL 类型事件
              • Event->SignalCount = 0;
            • 释放锁 CoreReleaseEventLock //gEfiCurrentTpl: TPL_HIGH_LEVEL Lock->OwnerTpl : TPL_HIGH_LEVEL
            • 通知注册在事件中的回调 Event->NotifyFunction (Event, Event->NotifyContext);
            • 加锁 //继续循环 //gEfiCurrentTpl: TPL_HIGH_LEVEL Lock->OwnerTpl : TPL_HIGH_LEVEL
          • 取消掩码位
          • 释放锁 CoreReleaseEventLock
      • 恢复任务优先级 gEfiCurrentTpl = NewTpl; // gEfiCurrentTpl: TPL_APPLICATION Lock->OwnerTpl : TPL_APPLICATION
      • end

    设计模式总结#

    1. 中断/异步处理：SignalEvent 仅做入队操作，将耗时操作放在 CoreRestoreTpl 中执行，模拟了中断下半部（Bottom Half）的处理逻辑。

    2. 优先级驱动的调度：事件根据其 NotifyTpl 等级排队，高优先级的事件永远优先于低优先级事件被处理。

    3. 锁的防重入设计：通过提升 TPL 来屏蔽中断，比普通的自旋锁更彻底，确保在操作全局资源时不会被 UEFI 的中断服务例程打断。

    CheckEvent#

    触发 EVT_NOTIFY_WAIT 类型事件

    • 加锁 CoreAcquireLock
    • 调用 CoreNotifyEvent
      • 移除排队队列 Event->NotifyLink
      • 加入待通知队列 gEventQueue
      • 置为对应的优先级掩码 gEventPending
    • 释放锁 CoreReleaseEventLock
    • 当 Event->SignalCount 置位时候，返回 EFI_SUCCESS 并清除置位。
      • 只有调用 SignalEvent 才能置位 Event->SignalCount
        • 典型做法是在 EVT_NOTIFY_WAIT 类型事件的回调函数中做 SignalEvent 动作

    WaitForEvent#

    触发 EVT_NOTIFY_WAIT 类型事件 内部调用 CheckEvent 如果不成功就一直等待

    • 只能在 TPL_APPLICATION 等级下使用
    • 进入死循环
    • 调用 CoreCheckEvent
    • 当Status != EFI_NOT_READY 退出循环 //需要调用SignalEvent
