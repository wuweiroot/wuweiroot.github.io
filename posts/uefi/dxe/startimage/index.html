    StartImage 与 ConnectController：驱动连接是怎么被触发的

    September 17, 2026

    StartImage 表面上只负责调用镜像入口点，但在 DXE 里它还承担一件事：按规范把镜像创建或修改过的 handle 连接起来。这也是日志里常见"Dispatcher 里跑着 Driver Binding 的 Supported()“的原因。

    现象#

    Dispatcher 启动某个驱动时，日志里出现总线绑定驱动的 Supported() / Start()。触发点并不在 Dispatcher，而在 StartImage 的收尾。

    StartImage 的骨架#

    MdeModulePkg/Core/Dxe/Image/Image.c:1764：

    1. 记录当前 handle database key；
    2. 调用镜像入口点；
    3. 入口点返回后，若镜像不是 EFI_APPLICATION，按规范连接新建 / 被修改的 handle（:1959-1961）。

    规范要求#

    Image.c:1950-1957 的注释引用了 UEFI 规范中 StartImage() 的 EFI 1.10 扩展：

    为兼容按 EFI 1.02 规范编写的驱动（它们不会在入口点里自己连接设备），StartImage() 必须在每个镜像启动前后监视 handle 数据库；只要有 handle 被创建或修改，就必须在返回前对这些 handle 以 Recursive = TRUE 调用 ConnectController()。

    两个实现细节：

    • 只对非 EFI_APPLICATION 类型生效（:1959）；
    • 连接对象是"本次运行期间 Key 发生变化"的 handle，而不是全部 handle。

    handle database key#

    • 每次安装协议接口，gHandleDatabaseKey 自增，并把对应 handle 的 Key 更新为新值（Hand/Notify.c:249-250）；
    • 因此"镜像启动前的 Key"是一条分界线：Key 更大的 handle 就是本次新建或被修改的。

    CoreConnectHandlesByKey#

    Hand/Handle.c:1541：

    1. 遍历 gHandleList，统计 Handle->Key > Key 的数量（:1557-1562）；
    2. 分配并收集这些 handle（:1570-1575）；
    3. 释放协议锁后逐个调用 CoreConnectController(handle, NULL, NULL, TRUE)（:1586）。

    CoreConnectController 做什么#

    Hand/DriverSupport.c:51：

    • 对目标 handle 遍历驱动绑定列表，逐个调用 Supported()；命中则调用 Start()；
    • Start() 产生的 child handle 会被递归连接（DriverSupport.c:232-237）。

    另外两条会触发连接的路径：

    路径 位置 说明
    安装协议接口时立即连接 Notify.c:255-264 驱动入口点里每装一个协议，都可能立刻触发一轮 Supported()
    卸载协议接口失败或仍有打开项时重连 Handle.c:690-695 重新连接全部驱动

    完整链路#

    CoreDispatcher (Dispatcher.c:405)
  └─ LoadImage + CoreStartImage (Image.c:1764)
        ├─ 镜像入口点：安装协议 / 创建 handle      →  Key 变化 (Notify.c:249)
        └─ 返回后：CoreConnectHandlesByKey (Image.c:1960 → Handle.c:1541)
              └─ CoreConnectController(..., TRUE) (Handle.c:1586 → DriverSupport.c:51)
                    ├─ 各驱动的 Supported()
                    ├─ 命中者 Start()
                    └─ child handle 递归连接 (DriverSupport.c:232)

    实用结论#

    1. Supported() 被频繁调用属于正常：每次启动驱动、安装协议、递归连接 child handle 都会轮询一遍绑定列表；
    2. 应用程序不会触发这个自动连接（:1959 排除了 EFI_APPLICATION）；
    3. 想降低连接开销：入口点少装协议、不创建无用 handle；Supported() 保持"轻”（尽早返回、少打印、不做设备枚举）；避免在 Start() 中产生大量 child handle。

    排查提示#

    • 日志中 Supported() 的顺序即可反映驱动绑定列表的顺序与递归层次；
    • 若某个设备始终没有被驱动接管，先确认其 handle 是否在"新建/修改"范围内（即是否由某次镜像执行产生），再确认绑定驱动的 Supported() 判断条件。
