    UEFI 内核数据结构：Handle 与 Protocol 数据库

    September 17, 2026

    DXE 内核用三个结构维护"对象—协议"的关系：IHANDLE、PROTOCOL_ENTRY、PROTOCOL_INTERFACE，另外还有两个用于注册的结构。本文按代码整理字段与它们之间的联系（以 EDK II 的 Dxe 内核为例，行号随版本略有差异）。

    EFI_HANDLE 是什么#

    EFI_HANDLE 就是 IHANDLE *（MdeModulePkg/Core/Dxe/Hand/Handle.h:17）：

    • UEFI 用它表示一个"对象"：一个设备控制器（Controller）、一个已加载的镜像（Image）都是 handle；
    • 驱动把自己提供的接口以 Protocol 的形式安装到 handle 上；
    • 内核通过 handle 上的协议找到对应驱动与设备。

    三个核心结构#

    IHANDLE（Handle.h:17-26）#

    字段 含义
    Signature 'hndl'，用于校验（CoreValidateHandle）
    AllHandles 挂到全局 gHandleList 的链表节点
    Protocols 本 handle 上所有 PROTOCOL_INTERFACE 的链表头
    LocateRequest 用于按协议遍历 handle 时的游标（配对 LocateHandle 的分批返回）
    Key 本 handle 最后一次被创建/修改时的 handle database key

    PROTOCOL_ENTRY（Handle.h:37-47）#

    协议数据库中的条目，每个不同的协议 GUID 一条：

    字段 含义
    AllEntries 挂到全局 mProtocolDatabase 的链表节点
    ProtocolID 协议 GUID
    Protocols 该协议在所有 handle 上的接口链表（PROTOCOL_INTERFACE.ByProtocol）
    Notify 为该协议注册的通知处理链表（PROTOCOL_NOTIFY）

    PROTOCOL_INTERFACE（Handle.h:55-70）#

    一个 handle 上安装的一个协议对应一个接口结构：

    字段 含义
    Link 挂到 IHANDLE.Protocols
    Handle 反向指针，指回所属 handle
    ByProtocol 挂到 PROTOCOL_ENTRY.Protocols
    Protocol 指向所属 PROTOCOL_ENTRY
    Interface 协议接口指针（真正的服务表/结构体地址）
    OpenList / OpenListCount 被打开的情况（OPEN_PROTOCOL_DATA 链表）与打开计数

    两个注册类结构#

    OPEN_PROTOCOL_DATA（Handle.h:74-83）#

    记录"谁以什么方式打开了这个接口"：

    字段 含义
    AgentHandle / ControllerHandle 打开者与被打开的控制器
    Attributes 打开方式（见下表）
    OpenCount 打开次数

    打开方式取值（MdePkg/Include/Uefi/UefiSpec.h:1295-1300）：

    值 属性 典型用途
    0x01 EFI_OPEN_PROTOCOL_BY_HANDLE_PROTOCOL HandleProtocol() 打开
    0x02 EFI_OPEN_PROTOCOL_GET_PROTOCOL 驱动内部获取接口
    0x04 EFI_OPEN_PROTOCOL_TEST_PROTOCOL 仅测试是否存在
    0x08 EFI_OPEN_PROTOCOL_BY_CHILD_CONTROLLER 父控制器为子控制器打开
    0x10 EFI_OPEN_PROTOCOL_BY_DRIVER 驱动声明占用该控制器
    0x20 EFI_OPEN_PROTOCOL_EXCLUSIVE 独占（如总线驱动枚举期间）

    PROTOCOL_NOTIFY（Handle.h:90-99）#

    协议通知注册：Protocol（目标协议）、Event（要触发的通知事件）、Position（上次通知到的位置，保证通知从上次之后继续）。

    三者关系#

    mProtocolDatabase  (LIST_ENTRY)          gHandleList  (LIST_ENTRY)
      │                                        │
      ▼                                        ▼
PROTOCOL_ENTRY (ProtocolID = GUID)         IHANDLE  (Signature='hndl')
      ├── Protocols ──────┐                    ├── Protocols ──────┐
      └── Notify ──► PROTOCOL_NOTIFY           │                   │
                                               ▼                   ▼
                        PROTOCOL_INTERFACE ◄───┴───────────────────┘
                          ├── Handle    → IHANDLE
                          ├── Protocol  → PROTOCOL_ENTRY
                          ├── Interface → 接口指针
                          └── OpenList  → OPEN_PROTOCOL_DATA[]

    一个接口对象同时挂在两条链上：handle 侧的 Link、协议侧的 ByProtocol。

    三条关系（精确表述）#

    1. 一个 handle 可以挂多个协议接口（IHANDLE.Protocols）——例如一个 PCIe 设备同时提供 DevicePath 与 PciIo；
    2. 一个协议 GUID 可以出现在多个 handle 上（PROTOCOL_ENTRY.Protocols）——例如 PciIo 安装到不同的 PCIe 设备；
    3. 同一个 handle 上的同一个 GUID 只对应一个 PROTOCOL_INTERFACE，因此接口数量是"各 handle 上实际安装的协议数之和"，而不是简单的"设备数 × 协议数"（不同设备安装的协议集合并不相同）。

    查找路径#

    接口 位置 做法
    CoreLocateProtocol Hand/Locate.c:600 由 GUID 找到 PROTOCOL_ENTRY，遍历其 Protocols，返回第一个有效接口
    CoreLocateHandle Hand/Locate.c:294 遍历 gHandleList，按 SearchType（AllHandles / ByRegisterNotify / ByProtocol）筛选
    CoreLocateHandleBuffer Hand/Locate.c:692 LocateHandle 的缓冲版本（分批遍历后一次性返回句柄数组）
    CoreGetNextLocateByProtocol Hand/Locate.c:82、:409 按协议继续找下一个 handle；配合 IHANDLE.LocateRequest 记录游标
    CoreValidateHandle Hand/Handle.h:241 校验 Signature，判断句柄是否有效

    安装、打开、卸载#

    操作 位置 要点
    安装协议 CoreInstallProtocolInterface（Hand/Handle.c:305） 找到/创建 PROTOCOL_ENTRY；建立 PROTOCOL_INTERFACE 并挂两条链；gHandleDatabaseKey 自增并更新 Handle->Key；触发协议通知
    打开协议 CoreOpenProtocol（Handle.c:986） 维护 OPEN_PROTOCOL_DATA 与 OpenListCount
    关闭协议 CoreCloseProtocol（Handle.c:1253） 递减打开计数，必要时移除记录
    卸载协议 CoreUninstallProtocolInterface（Handle.c:715） 先断开正在使用该接口的驱动（CoreDisconnectControllersUsingProtocolInterface，Handle.h:207）；失败则重新连接全部驱动（Handle.c:690-695）

    Handle->Key 与 gHandleDatabaseKey 的配合，是 StartImage 收尾时"连接本次新建/修改的 handle"的依据，详见 StartImage 与 ConnectController。

    全局变量与锁#

    名称 位置 说明
    mProtocolDatabase Hand/Handle.c:22 协议数据库（PROTOCOL_ENTRY 链表）
    gHandleList Hand/Handle.c:23 句柄数据库（IHANDLE 链表）
    gHandleDatabaseKey Hand/Handle.c:25 handle database key 计数器
    gProtocolDatabaseLock 声明于 Hand/Handle.h:248 访问上述数据库时持有；由 CoreAcquireProtocolLock / CoreReleaseProtocolLock（Handle.h:217 / :226）管理

    访问这两个数据库的代码必须持锁；CoreFindProtocolEntry 等函数在注释里明确要求"锁已持有"。
