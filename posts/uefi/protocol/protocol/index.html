    protocol 内核代码#

    • DxeCore 维护一个协议数据库，数据库中包含有句柄(Handle)、协议 (Protocol)和接口 (Interface)。
    • 与面向对象概念类比，协议等同于类，接口等同于类的实例。
    • 在 UEFI 概念中，一个句柄(Handle)上安装有一个或多个协议(Protocol)的具体实现(Interface)，针对 某个特定 协议，一个句柄上只允许安装一个对 应的接口 。

    IHANDLE#

    • EFI_HANDLE是指向某种对象的指针，UEFI用它来表示某个对象。
    • UEFI扫描总线后，会为每个设备建立一个Controller对象，用于控制设备，所有该设备的驱动以Protocol的形式安装到这个Controller中，这个Controller对象就是一个EFI_HANDLE对象。
    • 当我们将一个.efi文件加载到内存中时，UEFI也会为改文件建立一个Image对象，这个Image对象也是一个EFI_HANDLE对象。在UEFI内部，EFI_HANDLE被理解为IHANDLE.
    typedef struct {
  UINTN         Signature;
  /// All handles list of IHANDLE
  LIST_ENTRY    AllHandles;
  /// List of PROTOCOL_INTERFACE's for this handle
  LIST_ENTRY    Protocols;
  UINTN         LocateRequest;
  /// The Handle Database Key value when this handle was last created or modified
  UINT64        Key;
} IHANDLE;

    PROTOCOL_ENTRY#

    每个不同的协议在协议数据库中都有1个条目。列出了支持此协议的每个处理程序以及已注册通知的列表。

    typedef struct {
  UINTN         Signature;
  /// Link Entry inserted to mProtocolDatabase
  LIST_ENTRY    AllEntries;
  /// ID of the protocol
  EFI_GUID      ProtocolID;
  /// All protocol interfaces
  LIST_ENTRY    Protocols;
  /// Registerd notification handlers
  LIST_ENTRY    Notify;
} PROTOCOL_ENTRY;

    PROTOCOL_INTERFACE#

    安装在句柄上的每个协议都使用协议接口结构进行跟踪

    typedef struct {
  UINTN             Signature;
  /// Link on IHANDLE.Protocols
  LIST_ENTRY        Link;
  /// Back pointer
  IHANDLE           *Handle;
  /// Link on PROTOCOL_ENTRY.Protocols
  LIST_ENTRY        ByProtocol;
  /// The protocol ID
  PROTOCOL_ENTRY    *Protocol;
  /// The interface value
  VOID              *Interface;
  /// OPEN_PROTOCOL_DATA list
  LIST_ENTRY        OpenList;
  UINTN             OpenListCount;
} PROTOCOL_INTERFACE;

    联系#

    • 一个ihandle可以挂多个 PROTOCOL_INTERFACE

      一个设备有多个协议, 如同一个PCIE设备可以支持DevicePath协议和PciIo协议

    • 一个 PROTOCOL_ENTRY 下可以挂多个 PROTOCOL_INTERFACE

      一个协议可以有多个设备， 如同一个Pcio协议可以安装到不同的PCIE设备身上

    • PROTOCOL_INTERFACE 是不会重复的。

      PROTOCOL_INTERFACE数量 等于 设备*协议,一个设备一个协议唯一指定一个PROTOCOL_INTERFACE

    举例#

    For: RootBridge    
Status = gBS->InstallMultipleProtocolInterfaces (
                    &RootBridge->Handle,
                    &gEfiDevicePathProtocolGuid, RootBridge->DevicePath,
                    &gEfiPciRootBridgeIoProtocolGuid, &RootBridge->RootBridgeIo,
                    NULL
                    );
    • 上升当前TPL到TPL_NOTIFY
    • 得到第一个可变参数 Args // VA_START (Args, Handle);
    • 用Args解析出后面的参数 Protocol 和 Interface
    • 对于 DevicePath 类型的 Interface 通过 CoreLocateDevicePath 判断数据库中是否存在相同的 DevicePath。如果不存在再添加
      • Status = CoreLocateDevicePath (&gEfiDevicePathProtocolGuid, &DevicePath, &DeviceHandle);
      • 确保每个设备（Controller）通常有且仅有一个设备路径协议，用于唯一标识该设备在系统中的位置（如 PCI 总线、USB 端口等）
    • 调用 CoreInstallProtocolInterface 安装protocol接口
      • 打印出要安装protocol的GUID
      • 使用 CoreHandleProtocol 尝试打开此 Handle 下的 Protocol判断Protoclo是否已经安装过了，如果安装过了就返回
        • Status = CoreHandleProtocol (*UserHandle, Protocol, (VOID **)&ExistingInterface);
      • 对 mProtocolDatabase 上锁
      • 查询 Prococol对应的 PROTOCOL_ENTRY ，如果没有就创建，并将 PROTOCOL_ENTRY 挂在 mProtocolDatabase ，返回 PROTOCOL_ENTRY
      • 创建 PROTOCOL_INTERFACE 对象
      • 如果入参指向的Handle不存在则创建 IHANDLE 对象
        • 将 IHANDLE 挂在 gHandleList 上
      • 断言添加的 Interface 在 PROTOCOL_ENTRY 中是否是一的
      • 对 PROTOCOL_INTERFACE 赋值 
          Prot->Signature = PROTOCOL_INTERFACE_SIGNATURE;
  Prot->Handle    = Handle;
  Prot->Protocol  = ProtEntry;
  Prot->Interface = Interface;
      • 初始化 OpenProtocol 数据库 
            InitializeListHead (&Prot->OpenList);
    Prot->OpenListCount = 0;
      • 把 PROTOCOL_INTERFACE 挂在 IHANDLE 对象上
      • 把 PROTOCOL_INTERFACE 挂在 PROTOCOL_ENTRY 对象上
      • 通知 PROTOCOL_ENTRY 下所有挂载的event进行触发

    小结:

    1. 此锁的 TPL 为 TPL_NOTIFY。 DXE Foundation 操作 handle database 前必须取得 handle database 锁。一旦取得该锁，系统的当前 TPL 被提升至 TPL_NOTIFY。这意味着对 handle database 的 操作只能被 TPL 高于 TPL_NOTIFY 的代码所打断。 UEFI 规范对调用各种 Boot Service 时所处的 TPL 作了限制，其中规定调用 protocol 相关的 boot services 时 TPL 必须<=TPL_NOTIFY。这保 证了即使对 handle database 的操作被高于 TPL_NOTIFY 的代码所打断，由于 protocol 相关的 boot services 不允许被调用， handle database 资源的独享性不会被破坏。
