    CPER 与 APEI 结构：字段级说明

    September 16, 2026

    本文按结构层次整理 APEI 错误记录的字段定义：错误状态块、CPER 条目（Section Descriptor）、各 Section 的职责，以及 BERT / HEST / GHES / ERST / EINJ 的头部结构。字段名与位域来自 MdePkg/Include/IndustryStandard/Acpi64.h。

    记录的三层结构#

    ① 表           BERT / HEST / ERST / EINJ        描述"去哪里找记录、怎么通知、怎么读写"
② 错误状态块    Generic Error Status / Boot Error Region   存放记录的内存块（含块状态与长度）
③ CPER 条目     Error Data Entry + Section      实际的错误描述

    HEST 通过 ErrorStatusAddress 指向错误状态块；状态块内部按 DataLength 排放若干 CPER 条目；每个条目由一个 Section Descriptor 加一段 Section 数据组成。

    错误块状态（Error Block Status）#

    typedef struct {
  UINT32 UncorrectableErrorValid     : 1;
  UINT32 CorrectableErrorValid       : 1;
  UINT32 MultipleUncorrectableErrors : 1;
  UINT32 MultipleCorrectableErrors   : 1;
  UINT32 ErrorDataEntryCount         : 10;
  UINT32 Reserved                    : 18;
} EFI_ACPI_6_4_ERROR_BLOCK_STATUS;
    字段 含义 使用规则
    UncorrectableErrorValid 块内含有效 UE 记录 第一条 UE 置 1
    CorrectableErrorValid 块内含有效 CE 记录 第一条 CE 置 1
    MultipleUncorrectableErrors 多条 UE 已有 UE 且再追加 UE 时置 1
    MultipleCorrectableErrors 多条 CE 已有 CE 且再追加 CE 时置 1
    ErrorDataEntryCount 条目数 每追加一条 +1；上限 0x3FF

    块被消费（OS 读取或复位）后，这些标志位与计数必须一起清零，否则 OS 会重复处理或认为还有新记录。

    错误状态块#

    /* BERT 的 Boot Error Region 与 GHES 的 Generic Error Status 结构相同 */
typedef struct {
  EFI_ACPI_6_4_ERROR_BLOCK_STATUS BlockStatus;
  UINT32 RawDataOffset;
  UINT32 RawDataLength;
  UINT32 DataLength;
  UINT32 ErrorSeverity;
} EFI_ACPI_6_4_GENERIC_ERROR_STATUS_STRUCTURE;
    字段 含义
    RawDataOffset 原始数据（未按 CPER 解释的裸数据）起始偏移
    RawDataLength 原始数据长度
    DataLength CPER 条目区长度
    ErrorSeverity 块内最高严重级别

    严重级别取值：

    值 含义
    0x00 CORRECTABLE（可纠正，尚未纠正）
    0x01 FATAL（致命）
    0x02 CORRECTED（已纠正）
    0x03 NONE

    追加条目时必须同时更新 DataLength（条目区变长）与 RawDataOffset（原始数据被后移）；块级 ErrorSeverity 只保留最高级别，优先级为 FATAL > CORRECTABLE > CORRECTED。

    CPER Section Descriptor（Error Data Entry）#

    typedef struct {
  UINT8  SectionType[16];     // GUID
  UINT32 ErrorSeverity;
  UINT16 Revision;            // 0x0300
  UINT8  ValidationBits;
  UINT8  Flags;
  UINT32 ErrorDataLength;
  UINT8  FruId[16];
  UINT8  FruText[20];
  UINT8  Timestamp[8];
} EFI_ACPI_6_4_GENERIC_ERROR_DATA_ENTRY_STRUCTURE;
    字段 用途
    SectionType 16 字节 GUID，决定 Section 的解析方式（Processor / Memory / PCIe / Generic）
    ErrorSeverity 本条严重级别
    Revision 结构修订号，当前 0x0300
    ValidationBits 指示 FruId / FruText / Timestamp 是否有效
    ErrorDataLength 紧随其后的 Section 数据长度
    FruId 可寻址器件的标识（器件句柄/编号）
    FruText 可读文本（例如器件或位置描述），供运维直接阅读
    Timestamp 时间戳

    FruText 是这一层最容易被忽略、但对现场最有用的字段：错误记录在 OS/RAS 工具里会把它打出来，因此放"人能看懂的位置信息"比放编码编号更有效。

    Section 类型（规范级）#

    Section 承载内容 定位相关字段
    Processor 处理器错误：错误来源类型、处理器编号、bank / APIC ID、错误状态 bank 与处理器编号
    Memory 内存错误：错误类型、物理地址、地址掩码、器件/通道相关字段 物理地址 + 地址掩码
    PCIe 端口类型、AER 可纠正/不可纠正状态、Header Log、错误源 ID 端口类型 + 设备标识
    Generic 厂商自定义数据 由平台定义

    Memory Section 只提供"错误类型 + 物理地址（含掩码）"。把物理地址映射为通道 / DIMM / 机箱位置属于平台职责，通常通过补充字段或 FruText 表达。

    各 Section 的精确字段顺序与位域以 UEFI 规范中 CPER 章节为准；实现时建议直接对着结构体逐个字段赋值，不要手工拼字节。

    BERT#

    typedef struct {
  EFI_ACPI_DESCRIPTION_HEADER Header;
  UINT32                      BootErrorRegionLength;
  UINT64                      BootErrorRegion;      // 指向错误区域（GAS 之外的物理地址）
} EFI_ACPI_6_4_BOOT_ERROR_RECORD_TABLE_HEADER;

    BootErrorRegion 指向的内存块结构与"错误状态块"一致。典型用法：固件在启动阶段发现错误 → 追加 CPER 条目 → 更新长度与状态位，OS 启动后读取。

    要点：

    • 该表描述的是启动阶段遗留的错误，不是运行期错误通道；
    • 错误区域长度有限，追加前应检查 ErrorDataEntryCount 是否达到上限。

    HEST 与 GHES#

    typedef struct {
  EFI_ACPI_DESCRIPTION_HEADER Header;
  UINT32                      ErrorSourceCount;
} EFI_ACPI_6_4_HARDWARE_ERROR_SOURCE_TABLE_HEADER;

    HEST 后面紧跟 ErrorSourceCount 个错误源结构。错误源类型常量包括：

    值 类型
    0x00 IA32 机器检查异常（MCE）
    0x01 IA32 可纠正机器检查（CMC）
    0x02 IA32 NMI 错误
    0x06 / 0x07 / 0x08 PCIe Root Port / Device / Bridge AER
    其它 GHES 系列（通用硬件错误源）

    通用错误源（GHES v1）字段：

    typedef struct {
  UINT16                                      Type;
  UINT16                                      SourceId;
  UINT16                                      RelatedSourceId;
  UINT8                                       Flags;
  UINT8                                       Enabled;
  UINT32                                      NumberOfRecordsToPreAllocate;
  UINT32                                      MaxSectionsPerRecord;
  UINT32                                      MaxRawDataLength;
  EFI_ACPI_6_4_GENERIC_ADDRESS_STRUCTURE      ErrorStatusAddress;    // 错误状态块地址
  EFI_ACPI_6_4_HARDWARE_ERROR_NOTIFICATION_STRUCTURE NotificationStructure;
  UINT32                                      ErrorStatusBlockLength;
} EFI_ACPI_6_4_GENERIC_HARDWARE_ERROR_SOURCE_STRUCTURE;

    GHES v2 在此基础上追加 ReadAckRegister、ReadAckPreserve、ReadAckWrite（用于 OS 读取错误后的确认）。

    通知结构：

    typedef struct {
  UINT8  Type;
  UINT8  Length;
  EFI_ACPI_6_4_HARDWARE_ERROR_NOTIFICATION_CONFIGURATION_WRITE_ENABLE_STRUCTURE ConfigurationWriteEnable;
  UINT32 PollInterval;
  UINT32 Vector;                            // OS 侧中断向量
  UINT32 SwitchToPollingThresholdValue;
  UINT32 SwitchToPollingThresholdWindow;
  UINT32 ErrorThresholdValue;
  UINT32 ErrorThresholdWindow;
} EFI_ACPI_6_4_HARDWARE_ERROR_NOTIFICATION_STRUCTURE;
    字段 说明
    Type 通知方式（轮询 / 中断类）
    Vector 中断向量（GSIV）。填 0 时表能装、OS 也认，但错误不会送达 OS
    SwitchToPolling* 中断不可用时切轮询的阈值
    ErrorThreshold* 通知门限（值 + 窗口）

    ERST 与 EINJ#

    typedef struct {                       /* ERST */
  EFI_ACPI_DESCRIPTION_HEADER Header;
  UINT32                      SerializationHeaderSize;
  UINT8                       Reserved0[4];
  UINT32                      InstructionEntryCount;
} EFI_ACPI_6_4_ERROR_RECORD_SERIALIZATION_TABLE_HEADER;

typedef struct {                       /* EINJ */
  EFI_ACPI_DESCRIPTION_HEADER Header;
  UINT32                      InjectionHeaderSize;
  UINT8                       InjectionFlags;
  UINT8                       Reserved0[3];
  UINT32                      InjectionEntryCount;
} EFI_ACPI_6_4_ERROR_INJECTION_TABLE_HEADER;
    • ERST 后面是 InstructionEntryCount 条串行化指令项，每项描述"做什么动作、操作哪个寄存器区域（GAS）、用什么值/掩码"。它是服务接口描述，不是记录容器。
    • EINJ 同理，描述的是注入动作，记录仍走状态块。
    • 这两张表的可靠性取决于背后的固件服务实现（见 RAS 与 SMM）。

    常见实现缺陷#

    1. 追加条目时只更新 DataLength、忘了同步 RawDataOffset，导致原始数据被覆盖。
    2. ErrorDataEntryCount 未更新或达到上限后仍继续追加。
    3. 块级 ErrorSeverity 未按优先级保留（把 FATAL 降级成 CORRECTED）。
    4. ErrorDataLength 与实际写入的 Section 长度不一致，OS 解析越界。
    5. 复用已被 OS 消费的状态块，但未复位状态位与计数。
    6. 状态块位于外部内存（非 SMRAM）却在 SMM 内直接写入，未做校验。
    7. 结构修订号/长度字段未填，导致 OS 侧按错误布局解析。
