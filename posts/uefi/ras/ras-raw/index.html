    RAS 笔记（原稿）

    September 22, 2026

    RAS#

    • Reliability, Availability, Serviceability（可靠性、可用性、可维护性）。

    注意#

    • IBV封装层上报的sel日志是压缩后的信息，OEM定制的诊断信息是全量内容。

    • 开 FaultDiag 后启动期 MCA-UC/Deferred、PMIC、CXL 不再进 SEL，而运行期 SMM MCA 没有诊断通道，BERT 不受影响

    • AMD平台漏斗限制smi中断触发次数，管的是 SMM（固件） 的进出频率。目的是保 CPU 性能。

    • OEM漏斗限制ce上报次数，管的是 GHES/BMC（外部系统） 的接收频率。目的是保运维系统。

    RAS流程框架#

    PEI#

    AmdErrorLogPei → 建错误日志 HOB（gErrorLogHobGuid）

    • 从APOB中拿到错误信息存储到 HOB gErrorLogHobGuid

      ABL 事件(APOB) ──┐ CCD BIST/其他 PEIM ─┴→ [gErrorLogHobGuid 的循环缓冲] ←── gAmdErrorLogPpiGuid 写 │ ┌───────────────────┼────────────────────┬──────────────────┐ ▼ ▼ ▼ ▼ Display 驱动 CpmApobErrChk(RAS) Mem/PSP Dxe 服务协议暴露 POST 打印 ├─ OEM 回调 → BMC 自用 给后续驱动 └─ AddBootErrorRecordEntry → BERT → OS(APEI)

    • 即：屏幕（人）+ BERT（OS/APEI）+ BMC（OEM 回调），其中 BERT 这条是 RAS 的正规档案通道。

    AmdPlatformRasRsPei → 造 AMD_CPM_RAS_INFO_HOB（收 eDPC 状态）

    • 只用于打印

    漏斗算法#

    经典的泄漏桶算法实现，用于限制单位时间内的 SMI 频率

    通过单位时间内泄露条数，和中断发生间隔时间。计算出这段时间应该泄露的条数。再用累计条数-漏出的条数得到存在的条数和阈值进行比较。得到结果1

    • 阈值达到进入轮询模式
    • 注册轮询模式smi,遍历所有MCA寄存器找到错误

    计数器和泄露桶的区别#

    因为直接用“单位时间内的计数器”有两个致命缺陷：边界效应和无法平滑突发。泄漏桶的本质，就是用一种O(1) 的轻量级算法，去近似实现一个“滑动窗口”的效果。

    APEI#

    BERT#

    Boot Error Record Table

    • 记录启动时错误

    HEST#

    Hardware Error Source Table

    • 不存错误记录；描述"有哪些错误源、如何通知/使能"，并给出各错误状态块的地址
    • 运行期错误记录写在它指向的 GHES 错误状态块（CPER）里，由 SMM 填充

    ERST#

    Error Record Serialization Table

    • 定义 OS 如何把硬件错误记录持久化保存到非易失介质，以及重启后如何把记录读回来

    EINJ#

    Error Injection Table

    • 用于注错测试
