    RAS 与 SMM：错误记录在固件侧的处理与交付

    September 16, 2026

    本文整理 RAS 错误处理在 SMM 中的实现结构：SMM 与 SMI 的关系、通信模型与数据方向、同步/异步 SMI 对错误记录的影响、buffer 校验边界、实现要点与排查顺序。SMI 的注册与派发机制见 SMI 注册与触发流程。

    SMM 在 RAS 链路中的位置#

    错误处理放在 SMM，主要因为：

    1. 可在 OS 不知情的情况下完成记录、计数、隔离；
    2. 可访问部分运行期不可访问的寄存器与接口（错误源状态、地址翻译相关寄存器）；
    3. 与 SMI 天然绑定：错误源触发 SMI 后由 SMM 统一处理。

    代价是 SMI 进入/退出开销较大，会影响系统响应，因此高频错误必须限流（时间窗或计数）。

    SMM 通信模型#

    调用方发起请求 → 进入 SMM → 按 GUID 派发到 SMM 内的处理函数。

    • 通信协议：MdePkg/Include/Protocol/SmmCommunication.h；PPI 版本：MdeModulePkg/Include/Ppi/SmmCommunication.h
    • 通信数据 = 通信头 + 消息体。通信头包含三项：HeaderGuid（指定处理者）、MessageLength、Data
    • SMM Core（初始化、调度、派发）：MdeModulePkg/Core/PiSmmCore/，其中 PiSmmIpl.c 负责初始化，PiSmmCore.c 为核心，Dispatcher.c 调度 SMM 驱动，Smi.c 处理 SMI，Dependency.c 做 Depex 求值

    数据方向有两类，对错误记录的影响不同：

    • 请求-响应型（OS / DXE → SMM）：存在调用者上下文与返回 buffer，需要在返回前写回结果；
    • 通知型（固件 → OS）：SMM 生成记录后通过 SCI/NMI 通知，不依赖调用者。

    同步 SMI 与异步 SMI#

    类型 触发方式 上下文 对错误记录的影响
    同步 通过通信协议发起（GUID + buffer） 有调用者与返回 buffer 按请求填充 buffer；buffer 必须校验
    异步 硬件触发（GPI、电源按钮、定时器、USB）或软件端口写入（SwSmi） 无调用者 记录必须由 SMM 自行生成，不能依赖外部入参

    异步 SMI 无调用者上下文，需要在派发函数中遍历 CPU 状态寄存器定位触发源（硬件不记录 CPU 编号）。

    记录的两条交付路径#

    1. OS 主动读取：OS 通过 ACPI / ERST 串行化指令向固件请求记录，固件服务返回。
    2. 固件主动上报：SMM 生成 CPER，通过 SCI/NMI 通知，OS 侧 GHES 消费。

    两条路径都依赖 HEST 中描述的错误源与通知方式。描述与实现不一致时，表现为"固件侧已处理，OS 侧无记录"。

    Buffer 校验边界#

    SMM 只信任 SMRAM 内的数据，外部传入的 buffer 在使用前必须校验：

    • 校验 API：SmmIsBufferOutsideSmmValid()、SmmCopyMemToSmram()、SmmCopyMemFromSmram()（MdePkg/Include/Library/SmmMemLib.h）
    • 校验内容：地址范围是否与 SMRAM 重叠、长度是否越界、结构体长度/版本是否符合预期
    • 常见缺陷：直接解引用外部指针；用报文中的长度字段做循环边界而不设上限；把外部指针长期保存后再次使用

    实现要点#

    1. 失败路径必须复位状态位（Busy / Operation），否则请求方会一直轮询。
    2. SMM 内不调用 Boot / Runtime Services（gBS、gRT）。
    3. 高频错误需要限流。
    4. 上报通道失败时降级记录，不静默丢弃。
    5. 错误记录必须自包含（异步路径没有调用者上下文）。
    6. 单次 SMI 处理时间要有上限，避免阻塞导致看门狗或超时复位。
    7. 与 OS 共享的结构按规范更新（有效位、严重级别、记录数），字段只追加、不改义。

    排查顺序#

    1  SMI 是否到达        串口日志、状态码
2  GUID 派发是否命中   处理函数入口日志
3  buffer 校验是否通过  校验函数的返回值
4  记录是否生成        是否完成组装与写回
5  状态位是否复位      请求方是否继续执行
6  OS 是否收到         HEST 描述 + SCI/NMI 是否发出
