    RAS 架构与流程总览：分层、启动期与运行期链路

    September 22, 2026

    本文按分层结构整理服务器 BIOS 的 RAS 实现：各层职责、启动期与运行期两条主链、上报通路的取舍，以及限流算法与 APEI 四张表的定位。

    概念范围#

    Reliability、Availability、Serviceability（可靠性、可用性、可维护性）。

    注意事项#

    • IBV 封装层上报的 SEL 是压缩后的摘要信息，OEM 定制的诊断信息才是全量内容。
    • 开启故障诊断模式后：启动期的 MCA-UC/Deferred、PMIC、CXL 不再进 SEL；运行期 SMM 的 MCA 没有诊断通道；BERT 不受影响。
    • 硅片侧漏斗限制 SMI 触发次数，管的是 SMM（固件）的进出频率，目的是保 CPU 性能。
    • OEM 侧漏斗限制 CE 上报次数，管的是 GHES/BMC（外部系统）的接收频率，目的是保运维系统。

    两条漏斗管的对象不同：一个在固件内部，一个在固件与外部系统之间。

    代码架构分层#

    硅片侧#

    • 硅片能力层：硅片模块包
    • 硅片接口层：硅片 SDK 接口
    • 硅片配置层：硅片配置包
    • 平台框架层：平台模块包

    IBV 侧#

    • 封装上报：RAS 封装包

    OEM 侧#

    • ODM 定制
      • EC 上报阈值定制
      • BMC 上报定制、BMC 诊断模式

    分层架构#

    流程框架#

    PEI 阶段#

    错误日志 PEIM → 建错误日志 HOB（错误日志 HOB GUID）

    • 从引导期输出块中拿到错误信息，存到 HOB。
    引导期事件（早期输出块）──┐
CCD BIST / 其他 PEIM ─────┴→ [错误日志 HOB 的循环缓冲] ←── 错误日志 PPI 写入
                                    │
            ┌───────────────────────┼────────────────────┬──────────────────┐
            ▼                       ▼                    ▼                  ▼
    Display 驱动            启动期错误检查模块      内存 / PSP DXE     服务协议暴露
    POST 打印               ├─ OEM 回调 → BMC       自用              给后续驱动
                            └─ 追加启动期错误记录 → BERT → OS(APEI)

    即：屏幕（人）+ BERT（OS/APEI）+ BMC（OEM 回调）三条出口，其中 BERT 这条是 RAS 的正规档案通道。

    平台 RAS PEIM → 造平台 RAS 信息 HOB（收 eDPC 状态），只用于打印。

    漏斗算法#

    经典的泄漏桶实现，用于限制单位时间内的 SMI 频率。

    由单位时间内应泄漏的条数、中断发生间隔，算出这段时间应该泄漏的条数；再用累计条数减去已漏出的条数，得到现存条数，与阈值比较后得到结果。

    • 达到阈值即进入轮询模式：注册轮询模式 SMI，遍历所有 MCA 寄存器找错误。

    计数器与泄漏桶的区别#

    直接用"单位时间内的计数器"有两个致命缺陷：边界效应、无法平滑突发。泄漏桶的本质，是用一种 O(1) 的轻量级算法，去近似实现"滑动窗口"的效果。

    APEI#

    BERT#

    Boot Error Record Table

    • 记录启动时的错误。

    HEST#

    Hardware Error Source Table

    • 不存错误记录；描述"有哪些错误源、如何通知/使能"，并给出各错误状态块的地址。
    • 运行期错误记录写在它指向的 GHES 错误状态块（CPER）里，由 SMM 填充。

    ERST#

    Error Record Serialization Table

    • 定义 OS 如何把硬件错误记录持久化保存到非易失介质，以及重启后如何把记录读回来。

    EINJ#

    Error Injection Table

    • 用于注错测试。
